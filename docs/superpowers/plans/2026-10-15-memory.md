# Memory: agents remember across sessions and share what they know

**Goal:** what one agent learns about the code reaches every later agent that works on the same code, in this session or any later one. The memory lives on the code graph in FalkorDB, attached to the symbols it is about, so "who should hear this" is a graph question.

## Global constraints

- Deterministic delivery: what an agent hears is decided by graph queries, never by a model.
- Hook text is factual, not imperative (as all hook text today). No em or en dashes anywhere. Sentence case.
- Every memory is delivered to a task at most once.
- Local mode, remote mode (RPC) and the hosted workspaces all support it. New engine methods join the RPC allowlist and `RemoteAirspace`.
- Commits by the user only, no co-author lines.

## Graph

```
(:Note {id, text, kind, agent, task, at})-[:ABOUT]->(:Symbol)
(:Task)-[:RECALLED {at}]->(:Note)
(:Task)-[:RECALLED {at}]->(:ContractChange)
```

- `kind` is `note` (written by an agent or a person), `fix` (written by Airspace when a collision resolves).
- Text is 1 to 500 characters, stripped.
- A note can be about several symbols (one ABOUT edge each).

## Engine (`server/src/airspace/admission/memory.py`, methods exposed on `Airspace`)

| Method | Does |
| --- | --- |
| `remember(agent_id, task_id, qualnames, text, kind="note") -> str` | Writes a Note about those symbols (unknown qualnames: ValueError naming them). Returns its id. Logs an Event `noted`. |
| `recall(qualnames, exclude_task=None, limit=8) -> list[dict]` | What the graph remembers about these symbols, newest first: notes (any kind), and contract changes made by tasks other than `exclude_task` (current or past sessions). Each item: `{"id","kind": "note"|"fix"|"contract","symbol","text","agent","at"}`. For contract items, text reads "Contract changed: old -> new" (or "Renamed to X" / "Removed"). Also accepts file paths: a path means every symbol the file defines. |
| `memory_for_task(task_id, qualnames) -> list[dict]` | `recall` minus what this task already recalled and minus its own notes and changes; marks the returned items RECALLED. This is what hooks deliver. |
| `history(qualnames) -> dict` | `{"collisions": n, "notes": n, "changes": n, "last_at": t}` over these symbols, for pre-flight. |

Automatic `fix` notes: when a contract collision resolves because the held agent's retry fits the new signature (the engine already marks it `resolved`), write a `fix` note about the changed symbol: `"{held_agent}'s call {held_call} did not fit {new_sig} after {owner_agent}'s change. It cleared as {fixed_call}."` Store the held call text on the Collision when the hold is made and the fixed call text when it resolves (thread the call text through `CallSite.text` in `edit_analysis` call shapes so the engine has it). If either text is unknown, write `"{held_agent} was held at {symbol} after {owner_agent}'s change to {new_sig}, and cleared with a call that fits."`

## Delivery (hooks)

- **PreToolUse on an edit** (`handle_pre`, cleared or held): memory for the touched symbols and the callees of new calls, appended to the existing context or deny reason as one block:
  `Airspace memory: utils.text.slugify: agent-b's call slugify(post.title, allow_unicode=True) did not fit ... It cleared as slugify(post.title, unicode=True). (fix, Oct 14)`
- **PreToolUse on Read** of a .py file (`handle_any`): memory for the symbols the file defines, at most 5 items.
- **UserPromptSubmit** (`handle_prompt`): memory for the files and symbols the prompt names (reuse `note_interest_from_text` matching), returned as `additionalContext` so the agent starts the task knowing it.
- Always through `memory_for_task`, so nothing repeats within a task.

## Tools

- MCP: `remember(symbols: list[str], text: str)` and `recall(symbols: list[str])` (symbols may be short names or file paths; resolve like pre-flight's `resolve_symbol`).
- CLI: `airspace remember --root R --symbol S [--symbol S2] "text"` and `airspace recall --root R S [S2 ...]`.
- API (demo and workspace, workspace owner-only, X-Airspace on POST):
  - `GET /api/memory?symbols=a,b` -> `{"items": [...]}` (recall), `GET /api/memory/recent?limit=20` -> newest notes and fixes.
  - `POST /api/notes` `{"symbols": [...], "text"}` -> `{"id"}` (author "Tower", kind note).
- Pre-flight: each task in the answer gains `"history": {"collisions","notes","changes"}` over its symbols and cone, and the summary gains one sentence when any task touches code with past collisions, naming the symbol and count ("Routing touches flask.sansio.scaffold.Scaffold.route, which collided 3 times before.").
- `insights()` and `airspace insights` include the newest five notes.

## Web

- Tower (demo, replay and workspace): a "Memory" section in the sidebar under Activity, listing recent notes and fixes (symbol in mono, text, agent, relative time), live from `/api/memory/recent` (or the workspace variant). The collision panel shows the fix note for a resolved collision. A small "Add a note" form in the collision panel and the memory section (symbol prefilled where known), posting to `/api/notes`; hidden in replay.
- Pre-flight result: under each task's cone bar, "From earlier sessions: 3 collisions, 2 notes" when any; nothing when empty.
- Homepage "It remembers." card: copy and illustration show a real note travelling from one session to the next (Monday: held, the fix is written to the graph; Tuesday: a new agent touching slugify is told the fix before it writes the call).

## Tests

- Engine: remember/recall/memory_for_task (once per task, own items excluded, file paths), history counts, fix note on resolution with both call texts, the fallback text.
- Hooks through the real engine: an agent in a later session (new task id) gets the fix note on its first edit that calls the symbol, and on reading the file, and from its prompt; not twice.
- Remote mode: the same through the RPC.
- API, CLI, MCP, pre-flight history.
